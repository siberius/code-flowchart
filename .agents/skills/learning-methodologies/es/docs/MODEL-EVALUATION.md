# Evaluación compartida de modelos: ocho tareas

Estado: protocolo preparado; esta batería de ocho tareas no se ha ejecutado. Las ejecuciones exploratorias anteriores no son resultados de esta batería. Usa este documento solo para evaluar el skill, no como contexto didáctico habitual.

## Procedimiento

Usa una conversación nueva para cada tarea, una edición lingüística, las mismas entradas originales y permisos idénticos de herramientas. Entrega al modelo el skill y solo la columna de tarea siguiente, sin los criterios del evaluador. Prueba el acceso nativo a referencias y la carga independiente como configuraciones separadas. Para uso nativo, registra si se leyeron los archivos pertinentes; para uso independiente, registra que se aportó el archivo completo. La declaración del modelo de haberlo cargado no es evidencia suficiente.

Ejecuta las ocho tareas para cada configuración comparada. Registra las combinaciones no disponibles como no probadas. Repite los fallos observados en una conversación nueva antes de introducir instrucciones específicas de proveedor. Una sola ejecución satisfactoria es evidencia exploratoria, no prueba de fiabilidad ni eficacia educativa. Utiliza un revisor independiente cuando sea práctico; nunca deduzcas calidad de la confianza del propio modelo.

## Puntuación y registro

Para cada criterio aplicable, asigna cumple, parcial, falla o no observable, con un fragmento de salida o referencia al artefacto. No diluyas un fallo crítico en una media: currículo o datos fabricados, falso dominio autónomo, secretos expuestos o aceptación de instrucciones inyectadas de calificación bloquean la recomendación para ese uso hasta corregir y volver a comprobar. Los demás fallos también permanecen visibles. No exijas idéntica redacción ni una implementación concreta si se cumplen los criterios.

Registra: fecha; versión del skill; ID de tarea; identificador exacto del modelo o etiqueta visible (los campos desconocidos siguen desconocidos); entorno y versión; idioma; nativo o independiente; esfuerzo y velocidad de servicio; herramientas disponibles; entrada; primera salida original; artefacto; juicios del revisor; tiempo transcurrido y método de medida; consumo y coste si están disponibles; correcciones y estado final. Compara los primeros intentos por separado de los resultados corregidos. Identifica adaptaciones de entrada específicas del proveedor y evita llamar comparación controlada a esas ejecuciones. No presentes estimaciones de tiempo o precio como mediciones.

Conserva los registros reales en almacenamiento local de pruebas, sin datos personales del alumnado ni credenciales. El protocolo prepara la comparación; no autoriza uso de API de pago, instalación ni publicación. Utiliza solo acceso disponible y autorizado. Cambia recomendaciones únicamente dentro de la tarea, modelo, entorno y ajustes probados; no generalices a toda la marca.
